# AnyOCR：读取图片与扫描件

AnyOCR 通过 MCP 服务 `anyocr` 提供本地 OCR。所有识别都在本机完成，文件不会上传。

## 什么时候用

- 用户给了图片（截图、照片、扫描页），需要其中的文字。
- PDF 用普通方式读不出文字，或读出来是空的、乱码（多半是扫描件）。
- 要在一本扫描的书或讲义里找某个概念、公式、定理出现在哪几页。
- 用户想把扫描件 PDF 变成可搜索、可复制的 PDF。

已有文字层的普通 PDF 也能用，有文字的页会直接提取，不做 OCR。

## 工具

| 工具                  | 作用                                                                                     |
| --------------------- | ---------------------------------------------------------------------------------------- |
| `ocr_image`           | 识别一张图片，返回按阅读顺序排列的文字                                                   |
| `ocr_pdf`             | 按页读取 PDF 文字（`pages` 如 `"12-15"`），每页以 `<!-- page N -->` 开头，单次最多 30 页 |
| `search_pdf`          | 关键词搜索，返回页码和上下文（忽略空格、换行、大小写）                                   |
| `make_searchable_pdf` | 后台识别全书，生成带文字层的 PDF 并建立缓存，立即返回任务编号                            |
| `job_status`          | 查询后台任务进度                                                                         |

路径一律用绝对路径。

## 推荐流程

**短文档（几页）**：直接 `ocr_pdf`，读完即可。

**长文档（几十页以上）**，不要从头逐页读：

1. 先 `search_pdf` 搜关键词。
2. 如果结果提示“N 页是扫描页且尚未识别”：
   - 只关心少数几页时，用 `ocr_pdf` 读这几页（约 1 秒/页）。
   - 要在全书范围内查找时，调用 `make_searchable_pdf`（约 1 秒/页，300 页约 5 分钟）。期间每隔 30~60 秒用 `job_status` 查一次进度，可以先做别的事。完成后再 `search_pdf`。
3. 根据命中的页码，用 `ocr_pdf` 读取那几页及前后各一页，再回答用户。引用时注明页码。

识别结果会缓存，同一文件再次读取或搜索不会重复识别。

## 注意

- OCR 可能有个别错字，公式会以纯文本出现（如 `y' + P(x)y = Q(x)`），上下标可能丢失。引用公式时请结合上下文判断，必要时提醒用户核对原书。
- 未指定输出路径时，`make_searchable_pdf` 会在原文件旁生成 `<文件名>.ocr.pdf`。原文件所在目录不可写，或用户不希望修改目录时，传 `output` 指定位置。
- 首次调用会加载本地模型，第一次使用时还需下载约 100 MB，会多等一会儿。
